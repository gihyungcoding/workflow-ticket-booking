# ADR-0033: 이메일(비밀번호) 로그인은 이메일 소유를 확인한 뒤에만 허용한다

- **상태**: 채택됨 (ADR-0020 의 「이메일 가입은 소유 확인이 없다」는 전제를 보완)
- **날짜**: 2026-11-12
- **관련**: ADR-0020, ADR-0031, ADR-0032, `docs/product/features/email-verification-password-reset.md` §1-1·§3-3·§8

---

## 맥락

ADR-0020 은 소셜 자동 연결을 「이메일 소유가 확인된 계정」에만 하도록 좁혔다. 이메일 가입은 소유 확인이 없어 누구나 남의
이메일로 가입할 수 있었기 때문이다. 그 결과 이메일 가입 계정은 소셜 자동 연결 대상이 아니었다.

이메일 인증을 만들면서 정해야 하는 것이 생겼다.

- 인증하지 않은 계정을 **로그인시킬 것인가**. 막지 않으면 인증은 안내일 뿐이다
- 이미 있는 이메일 가입자는 전원 `email_verified=false` 다. 배포 순간 어떻게 되는가
- 남의 이메일로 먼저 가입(**선점**)해 두면 진짜 주인이 같은 이메일로 가입하지 못한다
- 소셜 로그인은 제공자 계정으로 이미 확인했는데 이메일 인증을 또 요구할 것인가

## 검토한 선택지

### A. 인증 전 이메일 로그인 차단 + 기존 가입자 재인증 + 미인증 재가입은 덮어쓰기 (채택)

- 장점: 이메일 가입 계정도 소유가 확인된 것만 남아 ADR-0020 의 조건이 이메일 계정에 성립한다. 선점 행은 메일함 주인만
  인증할 수 있어 쓸 수 없고, 진짜 주인은 다시 가입해 덮어쓴다
- 단점: 가입 직후 자동 로그인이 사라지고, 메일 발송에 로그인이 기댄다. 기존 가입자는 한 번 인증해야 한다

### B. 로그인은 허용하고 미인증은 일부 행위만 제한

- 장점: 메일이 늦어도 서비스를 쓸 수 있다. 가입 흐름이 거의 안 바뀐다
- 단점: 인증이 의미를 가지려면 제한할 행위가 있어야 하는데 예매가 아직 없다(주최자 쓰기뿐). 소셜 자동 연결의 신뢰 조건을
  충족하지 못한다

### C. 인증 뒤에 계정을 만든다 (가입 정보를 대기시켰다가 링크 확인 때 행 생성)

- 장점: 선점 행 자체가 생기지 않는다
- 단점: 가입 API·화면·테스트가 크게 바뀐다. 이메일 소유를 모르는 채 비밀번호가 담긴 대기 상태를 다뤄야 한다. 인증 메일을
  받은 피해자가 링크를 누르면 공격자의 비밀번호로 만들어지는 틈은 A 와 같다

## 결정

A. 이메일(비밀번호) 로그인은 `email_verified=true` 일 때만 되고, 인증 전에는 비밀번호가 맞은 경우에만 403
`EMAIL_NOT_VERIFIED` 와 인증 메일 발송으로 답한다. 기존 가입자는 `email_verified` 를 바꾸지 않고 로그인할 때 재인증을 요구한다.
순수 이메일 가입 미인증 행(비밀번호 있음·소셜 연결 없음)에 다시 가입하면 나중 가입의 값이 덮어쓰고 이전 토큰이 무효가 된다.
소셜 로그인은 차단하지 않는다. 비밀번호 재설정은 메일함 소유를 확인한 것이므로 인증도 겸한다. 인증·재설정 뒤에는 자동 로그인을
하지 않는다.

### 이유

- B 는 소셜 자동 연결의 신뢰 조건을 만들지 못한다. 이 기능의 한 목적이 그 조건을 이메일 계정에도 성립시키는 것이다
- C 는 선점 행을 없애는 대신 가입 전체를 다시 짠다. 남는 틈이 같아 비용만 크다
- 기존 가입자를 일괄 인증으로 인정하면 확인하지 않은 이메일이 「인증됨」으로 남아 ADR-0020 이 막으려던 선점 경로가 그 행들에
  남는다. 재인증은 기존 사용자가 한 번만 수고하면 된다
- 소셜 계정은 제공자가 이미 로그인을 확인했고 비밀번호가 없다. 이메일 인증을 요구해도 얻는 것이 적다

## 결과

- 좋아지는 것:
  - 인증된 이메일 계정과 제공자가 검증한 같은 이메일의 소셜 로그인이 ADR-0020 에 따라 자동 연결된다(소셜 쪽 코드 변경 없음)
  - 선점 가입이 진짜 주인을 막지 못한다
- 감수하는 것:
  - **남는 틈**: 피해자 가입 직후·인증 전에 공격자가 다시 가입하면, 피해자가 누른 링크가 공격자의 비밀번호로 계정을 인증한다.
    이전 토큰을 지우고, 메일에 「직접 가입하지 않았다면 무시」를 넣고, 인증 뒤 자동 로그인을 하지 않아 피해자가 비밀번호
    불일치를 알고 비밀번호 찾기로 복구하게 해 줄였을 뿐 완전히 막지 못한다
  - 기존 미인증 가입자의 비밀번호를 그 이메일을 아는 누구나 가입으로 덮어쓸 수 있다(비밀번호 찾기로 복구)
  - 메일이 안 오면 이메일로는 로그인하지 못한다(소셜은 가능). 메일 서비스 장애가 신규·재인증 사용자의 로그인에 닿는다
  - 비밀번호를 바꿔도 이미 발급된 로그인 토큰(최대 24시간)은 남는다(ADR-0012·0029 의 「필터가 DB 를 읽지 않는다」 유지)
- 되돌리려면: 로그인의 인증 확인을 지우면 인증이 안내가 된다. 그때 ADR-0020 의 자동 연결은 다시 소셜 계정만 대상이 된다

## 검사 가능한 제약

- 없음 — 로그인 허용 조건은 서비스 규칙이라 패턴 검사가 아니라 시나리오(인증 전 403·인증 후 200)로 확인한다
