# ADR-0023: 대기열 순번은 Redis 에 두고, 좌석 선점은 계속 DB 트랜잭션으로 처리한다

- **상태**: 채택됨
- **날짜**: 2026-11-04
- **관련**: ADR-0004, ADR-0005, ADR-0006, `docs/architecture/architecture.md` §7, `out/prd.md` FR-6~9·FR-14

---

## 맥락

PRD 는 오픈 순간 공연 하나에 최대 약 10만 명을 가정한다(`out/prd.md` §3). ADR-0004 는
「동시 접속 1,000명 초과」를 재검토 트리거로 두고, 그때 도입 순서를 **진입 제한(대기열) →
메모리 선점 계층 → 비동기 저장**으로 정해 두었다. 이번 PRD 가 그 트리거를 요구사항 단계에서
넘는다.

대기열에 대한 요구는 다음과 같다.

- 누른 순서대로 순번이 매겨지고, 앞·뒤 인원이 계속 줄어드는 것을 본다 (FR-6·7)
- 폰 잠금·앱 전환·새로고침·잠깐의 끊김에도 순번이 유지된다 (FR-8)
- 순번이 끊기면 이유와 지금 상태를 알린다. 같은 계정이 다른 기기에서 들어오면 순번이
  그 기기로 옮겨 가고, 원래 기기에서 「이 폰으로 가져오기」를 할 수 있다 (FR-9, 시안 `queue--error`)
- 서버가 재시작돼도 순번이 사라지면 안 된다 (PRD §5-1 대기열 유지)

순번 조회는 대기 중인 모든 관객이 몇 초마다 반복한다. 10만 명이 3초마다 조회하면 초당
3만 건이다.

## 검토한 선택지

### A. PostgreSQL 테이블 (시퀀스 + 상태 컬럼)

- 장점: 인프라가 늘지 않는다. 트랜잭션으로 순번 이동을 원자적으로 처리할 수 있다.
- 단점: 순번 조회(내 앞에 몇 명)가 매번 카운트 쿼리다. 초당 수만 건의 조회가 좌석 선점
  트랜잭션과 같은 커넥션 풀을 다툰다 — 대기열이 보호하려는 바로 그 DB 를 대기열이 포화시킨다.

### B. Redis — 대기열에만 (sorted set + 입장권 TTL 키)

- 장점: `ZADD`/`ZRANK` 가 O(log N) 이라 순번 조회가 DB 를 건드리지 않는다. 입장권은 TTL 키로
  자연 만료된다. 계정당 대기 슬롯 1개(기기 이동)를 키 하나로 표현할 수 있다. AOF 로 재시작에도
  순번이 남는다. ADR-0004 가 미리 정한 도입 순서의 첫 단계와 같다.
- 단점: 운영할 인프라가 하나 는다 (1인 개발 — product.md §6). 테스트에 Redis 가 필요하다.

### C. 애플리케이션 메모리 (단일 인스턴스)

- 장점: 가장 단순하다.
- 단점: 재시작하면 순번이 사라진다 — PRD 의 「대기열 유지」와 정면으로 부딪힌다.
  인스턴스를 늘릴 수 없다.

## 결정

**B — 대기 순번과 입장권은 Redis 에 두고, 좌석 선점·예매는 지금처럼 PostgreSQL
트랜잭션(유니크 제약 + 조건부 UPSERT, ADR-0004)으로 처리한다.** Redis 는 대기열 전용이다.

### 이유

A 는 대기열이 보호해야 할 DB 를 대기열이 포화시킨다. C 는 요구사항(재시작에도 유지)을
못 지킨다. B 는 대기열이 좌석 선점 앞단에서 동시 진입 수를 제한하므로, 선점 자체는 ADR-0004
구조로도 감당할 규모가 된다 — 메모리 선점 계층(ADR-0004 의 두 번째 단계)은 지금 도입하지
않는다.

## 결과

- 좋아지는 것: 순번 조회가 DB 와 분리된다. 좌석 선택 단계에 들어오는 동시 인원을 입장권
  발급 속도로 통제할 수 있다.
- 감수하는 것: Redis 운영(로컬 docker compose, 배포 환경 관리형 Redis). 테스트는
  Testcontainers(Redis·PostgreSQL)로 돌린다 — ADR-0006 이 좌석 선점 착수 전 전환을 이미 정해 두었다.
  Redis 장애 시 대기열 진입이 멈춘다(좌석 선점·조회는 계속 동작).
- 되돌리려면: 대기열 저장소를 인터페이스(`QueueStore`) 뒤에 둔다. 규모가 작아지면 DB 구현으로
  바꿀 수 있다.

### 재검토 트리거

- 좌석 선점 API p99 > 1초 (입장권 발급 속도를 낮춰도) → ADR-0004 의 두 번째 단계(메모리 선점)
- Redis 단일 노드 메모리 사용 70% 초과

## 검사 가능한 제약

- ARCH 후보: Redis 클라이언트 타입(`RedisTemplate` 등)은 `repository` 패키지(대기열 저장소
  구현)에만 둔다. 대기열 흐름 문서(booking-ux-03)를 쓸 때 `constraints.yaml` 에 추가한다.
