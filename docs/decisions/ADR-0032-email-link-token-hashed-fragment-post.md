# ADR-0032: 이메일 링크 토큰은 해시로 저장하고, 링크는 URL fragment 로, 확인은 POST 로 한다

- **상태**: 채택됨
- **날짜**: 2026-11-12
- **관련**: ADR-0021 (소셜 로그인 토큰의 URL fragment 전달 — 이 결정이 확장한다), ADR-0012, ADR-0031, `docs/product/features/email-verification-password-reset.md` §3-1·§3-3

---

## 맥락

이메일 인증과 비밀번호 재설정은 메일로 보낸 링크를 누른 사람이 그 메일함의 주인이라고 본다. 링크에 담긴 토큰은 그 자체가
권한이라 새거나 두 번 쓰이면 안 된다.

- 토큰은 **1회용**이어야 하고 만료된다. 서버가 쓴 적이 있는지를 기억해야 한다
- DB 가 새거나 로그를 보는 사람이 있어도 **링크를 만들 수 있으면 안 된다**
- 링크를 누르면 주소가 서버 접근 로그·브라우저 히스토리·`Referer` 에 남는다(ADR-0021 이 소셜 토큰에서 다룬 문제)
- 메일 서비스의 보안 검사기가 메일의 링크를 사용자보다 먼저 연다. 링크를 여는 것(GET)이 토큰을 소모하면 사용자가 누를 때는
  이미 쓴 링크다
- OWASP 는 토큰이 암호학적 난수이고 1회용이며 만료돼야 한다고 하고, 재설정 링크는 요청의 Host 를 믿지 않고 `no-referrer` 를
  둘 것을 권한다

## 검토한 선택지

### A. 난수 토큰을 SHA-256 해시로 DB 에 저장 + URL fragment 링크 + 확인은 POST (채택)

- 장점: DB 에 원문이 없다. 1회용은 조건부 `UPDATE`(`used_at IS NULL AND expires_at > now`)로 동시 클릭에도 한 번만 성공한다.
  fragment 는 서버로 가지 않아 로그·`Referer` 에 남지 않고, 토큰은 화면이 읽어 POST 로 보내니 링크를 미리 여는 검사기가
  스크립트를 돌리지 않는 한 토큰이 소모되지 않는다
- 단점: 테이블 하나가 늘고, 프론트가 fragment 를 읽어 지우는 코드가 필요하다

### B. 서명된 JWT 를 링크에 담는다 (서버에 저장하지 않음)

- 장점: 테이블이 필요 없다. 소셜 `pendingToken`(ADR-0012 의 JWT)과 같은 방식이다
- 단점: **1회용을 보장할 수 없다.** 서버가 쓴 적을 기억하지 않으므로 만료 전까지 몇 번이든 쓸 수 있다. 새 요청이 와도 이전
  링크를 무효로 만들 수 없다(선점 가입 방어가 이전 토큰 무효화에 기댄다 — ADR-0033)

### C. 토큰 원문을 DB 에 저장하고 쿼리 문자열 링크 + GET 확인

- 장점: 가장 단순하다
- 단점: DB 가 새면 모든 미사용 링크가 열린다. 쿼리 문자열은 로그·`Referer` 에 남고 GET 확인은 링크 검사기가 토큰을 소모한다

## 결정

A. 토큰은 32바이트 난수(`SecureRandom`)를 URL-safe Base64 로 쓴 43자이고 DB 에는 SHA-256 해시만 저장한다(`email_token`).
링크는 `{FRONTEND_BASE_URL}/…#token=…` 형태의 fragment 이고 요청의 Host 를 쓰지 않는다. 프론트는 토큰을 읽는 즉시 주소에서 지우고
`POST` 로 확인한다. 인증·재설정 화면에는 `Referrer-Policy: no-referrer` 를 둔다.

### 이유

- B 는 1회용과 무효화를 못 한다. 이 기능은 둘 다 필요하다
- C 는 DB 유출·로그·링크 검사기 세 가지에 모두 약하다. 셋 다 이 기능에서 실제로 일어나는 일이다
- A 의 비용(테이블·프론트 코드)은 이미 ADR-0021 에서 한 번 치른 방식을 재사용하는 정도다

## 결과

- 좋아지는 것:
  - 이후 이메일 링크(이메일 변경 확인 등)가 같은 구조를 쓴다
  - 토큰이 DB·로그·`Referer` 어디에서도 원문으로 드러나지 않는다
- 감수하는 것:
  - 링크를 스크립트 없이 열면 아무 일도 일어나지 않는다(JS 를 끈 브라우저는 인증하지 못한다)
  - 사용한 토큰·만료된 토큰 행이 쌓인다. 정리 작업은 이번 범위 밖이다
- 되돌리려면: 링크 형식과 확인 API 를 바꾸면 된다. 이미 발송된 링크는 만료(24시간·30분)로 사라진다

## 검사 가능한 제약

- 없음 — 「요청의 Host 로 링크를 만들지 않는다」는 `FRONTEND_BASE_URL` 단일 출처를 테스트(위조 Host 헤더)로 확인한다
