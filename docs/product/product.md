# 프로덕트 정의

**최종 갱신**: 2026-11-04

---

## 1. 한 문장

공연/행사 티켓 예매 서비스.

## 2. 문제

소규모 공연 주최자는 예매를 전화와 메신저로 받는다. 좌석 배정을 수기로 관리해
같은 자리를 두 번 파는 일이 생기고, 오픈·마감 시각은 공지 채널마다 따로 알린다.
관객은 지금 예매가 가능한지 확인하려면 직접 연락해야 한다.

인기 공연은 정해진 시각에 예매가 열리고 그 순간 최대 10만 명이 몰린다. 기기마다
카운트다운이 몇 초씩 다르고, 폰이 잠기면 대기 순번이 사라지고, 좌석을 한 자리씩만 고를 수
있어 일행 자리를 놓친다 (→ `out/prd.md` §1, 2026-11-04 추가).

## 3. 사용자

| 역할 | 무엇을 하는 사람 | 이 프로덕트로 무엇을 하나 |
|---|---|---|
| 관객 (예매자) | 공연을 보러 가고 싶은 일반 사용자 | 공연을 검색하고 좌석을 선택·결제해 티켓을 예매한다 |
| 주최자 (판매자) | 공연을 여는 사람 | 공연을 등록하고 좌석 배치·가격·오픈 시각을 설정하며 예매 현황을 관리한다 |
| 운영/관리자 | 서비스 전체를 운영하는 내부 인력 | 주최자 승인, 정산, 신고 처리 등 서비스 운영을 담당한다 |

역할 이름은 태스크의 `sub_categories` 값과 일치시킨다 (→ `docs/workflow/task-schema.md` §3).

## 4. 범위

### 하는 것

- 공연 조회/검색 (관객)
- 좌석 선택 및 선점 (관객) — 결제 전까지 일정 시간 좌석을 잠가 중복 예매를 막는다
- 공연 등록/관리 (주최자) — 좌석 배치·가격·오픈 시각 설정, 예매 현황 확인
- 서버 기준 시각 카운트다운과 오픈 직전 진입 보장 (관객) — ADR-0024
- 대기열 — 순번 유지, 끊김 사유 안내, 기기 간 순번 이동 (관객) — ADR-0023
- 매수 지정 연석 한 번에 선점 (관객, 1인 최대 4장)
- 무통장 입금 예약 → 입금 확인 → 예매 확정, 기한 경과 자동 취소 (관객) — ADR-0025
- 무료 취소 기간 안의 직접 취소, 다른 회원에게 표 양도 (관객)

### 하지 않는 것

- 온라인 결제 연동 — 카드·네이버페이·카카오페이는 수수료·계약 비용이 생겨 이번에도 뺀다 (ADR-0025)
- 은행 입금 자동 연동 — 입금 확인은 보호된 내부 API 를 사람이 호출한다 (ADR-0025)
- 환불 송금 자체 — 취소 시 환불 금액·기한 안내까지만 하고, 실제 송금은 서비스 밖에서 처리한다
- 운영/관리자 전용 기능 — 주최자 승인, 정산, 신고 처리 등은 다음 단계 (역할은 §3에 정의했지만 이번 단계 구현 대상 아님)

## 5. 성공 기준

| 기준 | 측정 방법 | 목표 |
|---|---|---|
| 주최자가 시스템만으로 공연 등록~예매 현황 확인을 끝낸다 | 파일럿 주최자 대상 전화·메신저 문의 건수 집계 | 등록~현황 확인 관련 문의 0건 |
| 관객이 문의 없이 예매 가능 여부를 확인한다 | 화면에서 실시간 좌석 상태(가능/선점/매진) 표시 여부 | 모든 공연 상세 화면에서 100% 표시 |
| 동일 좌석 중복 판매가 없다 | 좌석-예매 매핑의 유니크 제약 위반 로그 | 중복 판매 사례 0건 |
| 기기마다 카운트다운이 같다 | 웹·앱·PC·폰을 동시에 띄워 0이 되는 시점·버튼 활성 시점 비교 | 같다 (서버 판정 기준) |
| 대기열에서 튕기지 않는다 | 폰 잠금·앱 전환·새로고침 뒤 순번 비교 | 순번을 잃는 사례 0건 |
| 일행 3명 연석을 한 번에 잡는다 | 매수 지정 후 선점 요청 횟수 | 한 번의 선택으로 선점 |

## 6. 제약

- 1인 개발 — 운영·유지보수 부담이 큰 구성(다중 서비스, 별도 인프라 운영 등)은 피한다.
  구체적인 기술 선택과 근거는 ADR 로 남긴다.

## 7. 열린 질문

- ~~좌석 선점(홀드) 유지 시간~~ — 시안 가정값 7분, 무통장 예약 후에는 입금 기한(당일 오후 11:59)까지 (2026-11-04)
- 결제 연동은 언제, 어떤 PG로 붙일지 — 이번에도 무통장 입금만 둔다 (ADR-0025).
- 무료 취소 기한 이후 취소 수수료율 — 시안 가정은 「공연 7일 전 자정까지 무료」, 이후 수수료율은 미정.
- 대기열 순번을 얼마 동안 비활성이어도 유지할지 — 대기열 흐름 문서(booking-ux-03)에서 정한다.
- 좌석이 없는 공연(자유석/스탠딩)은 어떻게 다룰지 — 좌석 지정이 전제인 흐름과
  수량 기반 판매를 같은 모델로 둘지 별도로 둘지.
- 주최자 승인 절차 없이 누구나 공연을 등록하게 둘지 — 이번 단계는 운영자 기능이
  범위 밖이라, 당장은 무검증 등록을 허용할지 판단이 필요하다.
