# [관객] 흐름 2 — 공연 찾기와 오픈 전 대기를 시안대로 (booking-ux-02)

**상태**: 확정
**최종 갱신**: 2026-11-10

---

## 1. 요구사항

### 1-1. 배경

공연 목록·상세는 TASK-001·002 에서 이미 동작한다 (`performance-availability.md`). 화면은
흐름 1(TASK-017)에서 테마만 바뀌었고, 구조는 시안(ADR-0022)과 다르다.

| AS-IS | TO-BE (시안) |
|---|---|
| 목록: 세로 카드, 제목·상태만, 필터 UI 없음 | 홈: 맨 위에 **곧 열리는 공연 머리글**, 상태 칩 6개, 포스터가 있는 2열 카드 |
| 상세: 오픈·마감 일시를 글로 나열, 기기 시계 | 상세: **티켓온 기준 시각 카운트다운**, 0초에 모든 기기에서 동시에 켜지는 예매하기 (ADR-0024) |
| 구역 정보 없음 | 예매 4단계 미리 보기와 **구역 위치 시트** — 무대에서 어느 구역이 앞인가 (FR-3·4) |

시안 PRD 의 핵심 사람(정민지)이 오픈 직전 이 화면에서 묻는 것은 "지금 몇 초 남았나, 모든
기기에서 같은가"와 "어느 구역이 앞인가"다. 이 흐름은 그 두 질문까지 답한다. 0초 뒤에
들어가는 대기열은 흐름 3(booking-ux-03)이다.

## 2. 화면 설계

**UI 라이브러리**: MUI — ADR-0002
**디자인 정본**: `docs/product/design.md` · `design-tokens.css`
**시안**: `out/screens/home.html` · `concert.html` · `zone-map.html` — 흐름은 `out/index.html` 「공연 찾기와 오픈 전」

### 2-1. 이 화면에서 사용자가 하려는 일

**곧 열리는 공연을 찾아 들어가, 모든 기기와 같은 시계로 오픈을 기다리며 어느 구역을 노릴지
미리 정한다.**

### 2-2. 참조

`out/market/` 에 모은 스토어 화면·리뷰 (2026-11-04 수집, `out/conventions.json`).

| 서비스 | 이 화면에 해당하는 부분 | 우리에게 없는 것 |
|---|---|---|
| 티켓링크·예스24·타임티켓·NOL | 홈: 맨 위 검색창, 장르 칩·격자, 포스터 카드, 하단 탭바 5칸 (M1·M2·M4) | 검색, 장르, **포스터** |
| 티켓링크·예스24 | 티켓오픈 탭: 오픈 시각 모음 + 알림 설정 (M5·K3) | 오픈 알림 |
| 예스24·타임티켓 | 실시간 랭킹, 할인 전용 목록 (M3·M6) | 랭킹, 할인 |
| NOL·티켓링크 | 상세: 회차 선택, 좌석 배치도 — 리뷰 불만 A3 "이미 확대된 배치도" | **회차**, **구역 위치·순서** |

리뷰 불만 A2 (티켓링크·NOL): "오픈 시각에 로딩이 길거나 대기하다 튕겨서 표를 놓친다."

**대조 결과**: 검색·장르·탭바·랭킹·할인·오픈 알림은 시안이 이미 뺐다(`decisions.cut`). 없는
것 중 **포스터**와 **구역 위치**는 이번에 넣는다(A). **회차**는 좌석 모델과 함께 흐름 4 에서
바꾼다. A2 는 이 흐름에서 0초 재조회 금지(§8)로 일부 대응하고, 진입 보장은 흐름 3 이다.

### 2-5. 상태별로 무엇이 보이나

시안은 「오늘 오픈하는 공연이 있고, 상세는 오픈 4분 전」인 순간만 그렸다. 나머지 상태의
문구는 이 문서가 정한다 — 시안을 보강하면 시안 문구로 바꾼다 (design.md §5 「시안이 이긴다」).

| 화면 | 상태 |
|---|---|
| 홈 | 기본 · 로딩 · 빈 목록(칩별) · 오류 · 더 보기 실패 · 머리글 후보 없음 · 기준 시각 실패 · 포스터 없음 · 긴 공연명 |
| 상세 | 예정(카운트다운) · 0초 전환 · 예매 가능 · 매진 · 마감 · 공연 취소 · 로딩 · 없는 공연 · 오류 · 기준 시각 실패 · 포스터 없음 · 구역 1개 |
| 구역 시트 | 기본 · 구역 정보 미등록(등록 순서) · 묶음 5개 이상 |

**홈**

- **기본** — 시안 그대로. 카드 전체가 상세로 가는 링크다. 배지 문구는 design.md §5
  (취소는 "공연 취소", 칩은 시안대로 "취소")
- **머리글** — 후보가 있으면 "<언제>에 <공연명> 예매가 열려요" + "<공연명> 공연 보기 >".
  `<언제>` 는 기준 시각으로 오늘이면 "오늘 오후 6:00", 아니면 "11월 14일(토) 오후 2:00".
  공연명은 줄이지 않고 두 줄을 넘으면 말줄임. **후보가 없으면** "다가오는 공연을 골라 보세요", 바로가기 없음
- **로딩** — 카드 자리 4개(포스터 비율 유지), 머리글 자리 한 줄
- **빈 목록** — 전체: "다가오는 공연이 없어요". 칩: "<칩> 공연이 없어요" + "전체 보기"(칩을 전체로)
- **오류** — "공연 목록을 불러오지 못했어요" + 다시 시도. 머리글 조회만 실패하면 후보 없음과 같게
- **더 보기** — 남은 공연이 있을 때만. 실패하면 이미 보인 카드는 두고 버튼 자리에 "불러오지 못했어요 · 다시 시도"
- **기준 시각 실패** — 머리글 위 시각 줄을 숨긴다. 기기 시계로 대신 쓰지 않는다
- **포스터 없음 / 이미지 로드 실패** — 같은 비율의 회색 면(`--c-surface`) + 티켓 아이콘. 대체 텍스트는 "<공연명> 포스터"
- **긴 공연명** — 카드에서 두 줄 말줄임

**상세** — 시안에 없는 상태의 머리글·CTA:

| 상태 | 머리글 제목 | 아랫줄 | CTA |
|---|---|---|---|
| 예정 | 오픈까지 4분 32초 | 티켓온 기준 오후 5:55:28 · 폰과 PC가 같은 순간에 열려요 | 꺼짐 "예매하기 · 오후 6:00에 열려요" (오늘이 아니면 "11월 14일(토) 오후 2:00에 열려요") |
| 예매 가능 (0초 전환 포함) | 지금 예매할 수 있어요 | 11월 18일(수) 오후 11:59에 마감돼요 | 켜짐 "예매하기" → `/performances/:id/queue` |
| 매진 | 모든 좌석이 팔렸어요 | — | 꺼짐 "매진" |
| 마감 | 예매가 마감됐어요 | — | 꺼짐 "예매 마감" |
| 공연 취소 | 공연이 취소됐어요 | — | 없음 |

- **카운트다운 표기** — 1일 이상 "3일 4시간", 1시간 이상 "2시간 15분", 1시간 미만 "4분 32초",
  1분 미만 "32초". `role="timer"` 와 `aria-label` 에 같은 문구. 숫자는 고정폭(`.num`)
- **0초 전환** — 기준 시각이 `openAt` 에 닿는 순간 다시 조회하지 않고 「예매 가능」으로 바뀐다
  (남은 좌석이 0 이면 「매진」). 같은 공연을 연 기기들이 같은 순간 바뀐다
- **기준 시각 실패** — 측정이 실패하면 카운트다운 대신 "기준 시각을 맞추지 못했어요" + 다시 맞추기.
  CTA 는 꺼짐 그대로 (기기 시계로 켜지 않는다)
- **화면 복귀** — 탭이 다시 보이면(`visibilitychange`) 기준 시각을 다시 측정한다
- **구역 1개** — "구역 위치 보기" 행을 숨긴다. 구역이 없는 공연(좌석 0)은 없다 (등록 검증)
- **로딩** — 머리글·포스터 자리 · **없는 공연** — "찾는 공연이 없어요" + 홈으로 · **오류** — "공연 정보를 불러오지 못했어요" + 다시 시도
- 「오픈 5분 전부터 가벼운 대기 화면」 안내는 넣지 않는다 (§8)

**구역 시트**

- **기본** — 배치도 + 묶음 행 + 확인. 흐린 바탕을 눌러도 닫힌다. 뒤로 가기는 시트를 닫는다
- **구역 위치 미등록** — 등록 때 `zones` 를 주지 않은 공연은 구역마다 묶음 하나, 순서는 등록 순서. 설명 줄 없음
- **묶음 5개 이상** — 배치도를 그리지 않고 묶음 행만 보인다 (고리 4겹까지)
- 행 "구역 위치 보기"의 아랫줄 — 첫 묶음의 세부 구역이 2개 이상이면 "<첫> 무대 바로 앞 → <끝> 맨 뒤"
  (시안 "F1 무대 바로 앞 → F4 맨 뒤"), 아니면 전체 구역의 첫·끝

**대기열 임시 화면** (`/performances/:id/queue`, 흐름 3 이 교체) — 앱바 뒤로 + "대기열을 준비하고 있어요" + 공연으로 돌아가기.

## 3. 데이터·API 명세

### 3-1. 스키마 (`V6__add_poster_and_zones.sql`)

```sql
ALTER TABLE performance ADD COLUMN poster_url VARCHAR(500);

CREATE TABLE performance_zone (
    id              BIGSERIAL PRIMARY KEY,
    performance_id  BIGINT NOT NULL REFERENCES performance(id),
    grade           VARCHAR(20) NOT NULL,      -- seat.grade 와 같은 값 (SectionRequest.grade 상한 20)
    area            VARCHAR(30) NOT NULL,      -- 묶음 이름 "플로어", "1층 지정석"
    area_note       VARCHAR(60),               -- "무대 앞 바닥, F1이 가장 앞"
    stage_order     INT NOT NULL CHECK (stage_order > 0),   -- 무대에서 가까운 순 1, 2, …
    UNIQUE (performance_id, grade),
    UNIQUE (performance_id, stage_order)
);
```

기존 공연은 `poster_url` 이 NULL 이고 `performance_zone` 행이 없다 — 응답은 §3-3 대로 채운다.

### 3-2. 서버 시각

```
GET /api/time            permitAll · Cache-Control: no-store
200 { "now": "2026-11-11T08:55:28.123Z" }       ← 주입된 Clock (ADR-0005)
```

### 3-3. 공연 API 변경

**등록** `POST /api/performances` — 선택 필드 2개 추가. 주지 않으면 지금과 같다.

```jsonc
{
  "title": "…", "venue": "…", "startAt": "…", "openAt": "…", "closeAt": "…",
  "sections": [ { "grade": "F1", "price": 150000, "rowStart": "A", "rowEnd": "E", "seatsPerRow": 20 }, … ],
  "posterUrl": "https://cdn.example.com/luminous.jpg",     // 선택. https 만, 500자 이하
  "zones": [                                                // 선택. 무대에서 가까운 묶음부터
    { "area": "플로어", "note": "무대 앞 바닥, F1이 가장 앞", "grades": ["F1", "F2", "F3", "F4"] },
    { "area": "1층 지정석", "note": "플로어를 둘러싼 아래층", "grades": ["1층"] },
    { "area": "2층 지정석", "note": "가장 바깥 위층", "grades": ["2층"] }
  ]
}
```

| 검증 | 응답 |
|---|---|
| `posterUrl` 이 https 절대 URL 이 아니거나 500자 초과 | 400 `INVALID_POSTER_URL` |
| `zones[].area` 공백·30자 초과, `note` 60자 초과, `grades` 비어 있음 | 400 `INVALID_REQUEST` (Bean Validation, ADR-0010) |
| `grades` 에 `sections` 에 없는 등급 | 400 `ZONE_GRADE_UNKNOWN` |
| 한 등급이 두 번 나옴 | 400 `ZONE_GRADE_DUPLICATED` |

`stage_order` 는 `zones` 를 펼친 순서(묶음 순서 → 묶음 안 `grades` 순서)다. `zones` 에 없는
등급은 그 뒤에 `sections` 순서로 붙고, 묶음 이름은 등급 이름, 설명은 없다. `zones` 를 주지 않으면
모든 등급이 이렇게 된다. **수정**(`PUT`)은 바꾸지 않는다 — 포스터·구역 수정은 범위 외.

**응답** — `PerformanceResponse` 에 `posterUrl`(없으면 키 생략, 목록·상세 모두). 상세의
`sections` 는 `stageOrder` 순으로, 원소에 3필드 추가:

```jsonc
"sections": [
  { "grade": "F1", "price": 150000, "seatCount": 100, "area": "플로어", "areaNote": "무대 앞 바닥, F1이 가장 앞", "stageOrder": 1 },
  …
]
```

**머리글 후보** — `GET /api/performances/next-opening` (permitAll)

```
200 PerformanceResponse      ← 취소되지 않았고 now < openAt 이고 startAt >= now 인 공연 중 openAt 이 가장 이른 것 (같으면 id 작은 것)
204                          ← 없음
```

선택 규칙은 `PerformanceService` 한 곳에 둔다. 스크랩이 생기면 이 정렬의 1순위만 바꾼다 (§7).

## 4. 흐름

```
홈 진입
  ├─► GET /api/time ×3 ──► 왕복이 가장 짧은 표본으로 offset = serverNow + rtt/2 − 기기시각
  ├─► GET /api/performances/next-opening ──► 머리글 (204 면 일반 문구)
  └─► GET /api/performances?status=&page=0&size=20 ──► 카드 ──(더 보기)──► page+1
                                     │ 카드
                                     ▼
상세 진입 ──► GET /api/performances/{id} ─┐
           └► useServerClock (offset) ────┤
                                          ▼
                        기준 시각 = 기기시각 + offset, 1초마다 표시 갱신
                                          │
              ┌─ 기준 시각 < openAt ──► 「예정」 카운트다운, CTA 꺼짐
              └─ 기준 시각 ≥ openAt ──► 「예매 가능」(좌석 0 이면 「매진」), CTA 켜짐   ← 재조회 없음
                                          │ 예매하기
                                          ▼
                       /performances/:id/queue (임시 화면 — 흐름 3 이 대기열 진입 + 서버 판정으로 교체)

탭이 다시 보임 (visibilitychange) ──► offset 재측정
```

0초에 켜지는 것은 표시다. 먼저 들어가는 것은 서버가 막는다 — 대기열 진입 API(흐름 3)가
`Clock` 으로 판정한다 (ADR-0024).

## 5. 완료 조건

### Task A (백엔드)

- [ ] `GET /api/time` 이 인증 없이 200 과 주입된 `Clock` 의 시각을 `now`(ISO-8601 UTC)로 돌려주고, 응답에 `Cache-Control: no-store` 가 있다
- [ ] `posterUrl`·`zones` 없이 등록하면 지금과 같이 201 이고, 상세 `sections` 는 등록 순서대로 `stageOrder` 1, 2, … 와 `area` = 등급 이름을 갖는다
- [ ] `zones` 를 주고 등록하면 상세 `sections` 가 `zones` 를 펼친 순서의 `stageOrder` 로 정렬되고 `area`·`areaNote` 를 갖는다. `zones` 에 없는 등급은 그 뒤에 붙는다
- [ ] `posterUrl` 이 `http://`·상대 경로·501자면 400 `INVALID_POSTER_URL`, `zones` 에 없는 등급이면 400 `ZONE_GRADE_UNKNOWN`, 중복 등급이면 400 `ZONE_GRADE_DUPLICATED` 이고 공연·좌석·구역 행이 생기지 않는다
- [ ] 목록·상세 응답에 `posterUrl` 이 있고, 없는 공연은 키가 없다
- [ ] `next-opening` 이 아직 열리지 않은 공연 중 `openAt` 이 가장 이른 1건을 돌려준다. 취소된 공연·이미 열린 공연·지난 공연은 고르지 않고, 후보가 없으면 204
- [ ] V6 마이그레이션이 기존 데이터가 있는 DB 에 적용되고 기존 공연의 목록·상세 응답이 바뀌지 않는다(`posterUrl` 없음, `sections` 에 기본 구역값만 추가)

### Task B (프론트 — 기준 시계·상세·구역 시트)

- [ ] 기기 시계가 서버보다 3초 빠르게 설정돼 있어도 카운트다운이 서버 시각 기준으로 표시되고, CTA 가 서버 시각의 `openAt` 에 켜진다 (오프셋 주입 테스트)
- [ ] 기준 시각이 `openAt` 에 닿으면 상세 API 를 다시 부르지 않고(그 순간 호출 0회 — ADR-0026) 머리글이 "지금 예매할 수 있어요", CTA 가 켜진 "예매하기"로 바뀐다. 남은 좌석이 0 이면 「매진」으로 바뀐다
- [ ] 카운트다운이 1일 이상·1시간 이상·1시간 미만·1분 미만에서 각각 "3일 4시간"·"2시간 15분"·"4분 32초"·"32초" 형식이고 `role="timer"` 의 `aria-label` 이 같다
- [ ] `GET /api/time` 이 실패하면 카운트다운 대신 "기준 시각을 맞추지 못했어요" + 다시 맞추기가 보이고 CTA 는 꺼짐이다
- [ ] 탭이 다시 보이면 `GET /api/time` 을 다시 호출한다
- [ ] 예매 가능·매진·마감·공연 취소 상태가 §2-5 표의 머리글·CTA 로 보인다
- [ ] 켜진 "예매하기"를 누르면 `/performances/:id/queue` 로 가고 "대기열을 준비하고 있어요"가 보인다
- [ ] 가격이 `sections` 의 최솟값~최댓값("110,000~150,000원"), 한 가격이면 "150,000원"으로 보인다
- [ ] "구역 위치 보기"를 누르면 시트가 열리고, 배치도와 묶음 행이 `stageOrder` 순("플로어 F1~F4 / 무대 앞 바닥, F1이 가장 앞 / 150,000원")으로 보인다. 확인·흐린 바탕·뒤로 가기로 닫힌다
- [ ] 구역이 1개인 공연은 "구역 위치 보기" 행이 없고, 묶음이 5개 이상이면 배치도 없이 행만 보인다
- [ ] 포스터가 없거나 이미지 로드가 실패하면 회색 면 + 아이콘이 같은 크기로 보인다
- [ ] 제목이 없는 앱바(상세·가입·역할 선택)에 빈 `h1` 이 없다 (TASK-018 drift)
- [ ] 없는 공연 404 → "찾는 공연이 없어요" + 홈으로, 그 밖의 실패 → "공연 정보를 불러오지 못했어요" + 다시 시도
- [ ] 375px 에서 `concert.html`·`zone-map.html` 과 나란히 띄워 구조·문구·색이 같다 (회차·5분 전 안내는 §8 의 차이)

### Task C (프론트 — 홈)

- [ ] `next-opening` 후보가 오늘(기준 시각, 한국 시간) 열리면 "오늘 오후 6:00에 <공연명> 예매가 열려요", 다른 날이면 "11월 14일(토) 오후 2:00에 …"가 보이고, "<공연명> 공연 보기"가 그 상세로 간다. 204 면 "다가오는 공연을 골라 보세요"만 보인다
- [ ] 머리글 위 "티켓온 · 11월 11일(수) 오후 5:50"이 기준 시각이고, 기준 시각 측정이 실패하면 이 줄이 없다
- [ ] 칩을 누르면 해당 `status` 로 첫 페이지를 다시 불러오고 누른 칩만 `aria-pressed="true"` 다
- [ ] 카드가 배지·공연명·시작 일시(항상 날짜 + 시각)·장소를 보이고, 예매 가능은 "남은 좌석 N석", 예정은 "<오픈 일시> 오픈"(오늘이면 "오늘 오후 6:00 오픈")을 덧붙인다. 카드를 누르면 상세로 간다
- [ ] 공연이 20개를 넘으면 "더 보기"가 보이고 누르면 다음 20개가 아래에 붙는다. 다 불러오면 버튼이 없다. 실패하면 이미 보인 카드는 그대로이고 "불러오지 못했어요 · 다시 시도"가 보인다
- [ ] 빈 목록은 전체면 "다가오는 공연이 없어요", 칩이면 "<칩> 공연이 없어요" + 전체 보기가 보인다
- [ ] 목록 실패 시 "공연 목록을 불러오지 못했어요" + 다시 시도, 로딩 중엔 카드 자리 4개가 보인다
- [ ] "내 예매" 행이 없다 (흐름 5)
- [ ] 375px 에서 `home.html` 과 나란히 띄워 구조·문구·색이 같다 (카드 일시·내 예매는 §8 의 차이)

## 7. 범위 외

**다음 흐름에서 한다**

- 회차(1회·2회)와 회차별 좌석 — 흐름 4. 예매 1단계(회차·매수)에서 좌석 모델과 함께 바꾼다
- 대기열 진입·순번·서버의 오픈 판정 — 흐름 3 (ADR-0023·0024). 이번엔 임시 화면까지
- 오픈 5분 전 진입 보장(FR-5)과 그 안내 문구 — 흐름 3
- 내 예매 진입(홈의 "내 예매" 행) — 흐름 5
- 스크랩과 「스크랩 많은 순」 머리글 우선순위 — 별도 기능 후보 (2026-11-10 사용자 요청). 시안에
  스크랩 버튼이 없어 시안부터 그려야 한다. 머리글 선택 규칙을 `next-opening` 한 곳에 둔 이유다

**하지 않기로 했다**

- 검색·장르·하단 탭바·랭킹·할인 목록·오픈 알림 — 시안이 뺐다 (`out/index.html` `decisions`)
- 포스터 업로드·수정, 구역 위치 수정, 주최자 등록·수정 폼 변경 — 시안 PRD §5-3 「주최자 쪽 변경 없음」.
  API 필드만 둔다
- 배치도 확대·이동 — 리뷰 불만 A3. 한 화면에 전체
- 모션 토큰 — 이 흐름에 새 애니메이션이 없다 (TASK-018 drift 는 다음에 모션이 생길 때)

## 8. 주요 결정 사항

| 결정 | 이유 | 범위 | ADR |
|---|---|---|---|
| 0초가 되면 화면은 **다시 조회하지 않고** 기준 시각만으로 「예매 가능」으로 바뀐다. 최종 판정은 진입 요청에서 서버가 | 같은 순간 10만 기기가 상세를 다시 부르면 그 자체가 진입 장애(A2)다. 표시와 판정을 나눈 ADR-0024 의 연장 | **전체** — 흐름 3 대기열, 흐름 4 선점 7분, TASK-018 역할 선택 5분 | ADR-0026 |
| 기준 시각을 못 맞추면 기기 시계로 대신하지 않는다 | 기기 시계 대체는 이 흐름이 고치려는 문제 그 자체 | 이 기능 + 흐름 3 | — |
| 구역 위치는 묶음(`area`) + 무대 기준 순서(`stage_order`)로 저장하고 배치도는 일반 규칙(첫 묶음은 쌓기, 나머지는 바깥 고리)으로 그린다 | 공연장마다 그림을 등록받지 않고 시안 모양을 얻는다. 흐름 4 의 구역 단계도 같은 순서를 쓴다 | 이 기능 + 흐름 4 | — |
| 홈 머리글은 `next-opening` 한 API 가 고른다 (지금은 가장 가까운 오픈) | 선택 규칙을 한 곳에 두면 스크랩 같은 우선순위가 생겨도 정렬만 바뀐다 | 이 기능 | — |
