# Phase 1 설계 점검 — 놓치기 쉬운 여덟 가지

`wf-plan` Step 1.5 · 2 · 4 에서 참조한다. 모두 **실사용에서 Phase 2a·4 까지 가서야 드러난**
것들이다. 각각 Phase 1 에서 5분이면 확인된다.

---

## 1. 화면 간 이동도 flow 다 (Step 4 — route 가 Frontend 일 때)

`design.flows` 에 **화면 안의 상태**(기본·로딩·빈·오류)만 적고 **화면 사이의 이동**을
빼기 쉽다. 이동이 flow 에 없으면 구현 단계에서 링크를 추가하고도 범위 이탈로 기록되지
않아, Phase 4 의 `scope_deviations` 대조에서야 사후 발견된다.

route 가 `Frontend` 이면 **최소 1개 flow 가 화면 간 이동**이어야 한다.

```jsonc
{ "id": "F5", "name": "목록 카드 → 상세 이동",
  "covers": ["AC-1"], "steps": ["카드 클릭", "/performances/:id 로 이동"] }
```

이동이 하나도 없는 화면(단일 화면 앱)이면 `route_reason` 에 그렇게 적는다.

## 2. 외부 리소스·프리셋 값은 사용처부터 본다 (Step 2)

웹폰트 굵기, 라이브러리 테마 프리셋, CDN 에서 받는 에셋 버전처럼 **요청 파라미터로 값을
지정하는** 것은, 지정하기 전에 **실제로 쓰는 곳의 현재 값**을 코드베이스에서 먼저 확인한다.

임의로 정하면 쓰지 않는 값을 받거나(굵기 600·700 을 요청했는데 실사용은 400·500),
쓰는 값을 못 받는다. 그 차이가 렌더에서 드러나는 것은 Phase 4 다.

## 3. 타입을 넓히는 변경은 새로 열린 입력 범위를 적는다 (Step 4)

`Integer → BigDecimal`, `int → long`, `enum → String` 처럼 **받을 수 있는 값의 범위가
넓어지는** 변경이 포함된 태스크는, `design.unresolved` 에 **"이 변경으로 새로 도달
가능해지는 입력 범위"** 를 적는다.

```jsonc
"unresolved": [
  "price: Integer → BigDecimal. 새로 도달 가능: 소수, 지수 표기(1e400), int 범위 초과값"
]
```

`coverage-policy.md` §2-1 의 타입별 표는 **바뀐 뒤의 타입**에 대본다. 타입이 바뀌면서
생기는 새 입력 공간은 **바뀌기 전과 비교해야** 보인다 — 표만으로는 놓친다.

## 4. ADR 이 이 태스크를 지목하는지 본다 (Step 1.5)

ADR 은 본문을 읽는 데서 끝나지 않는다. **「검사 가능한 제약」 절을 열어, 이 태스크를
지목하는 항목이 있는지** 확인한다.

```
ADR-0010 §검사 가능한 제약
  - ARCH-004: @RequestBody 에는 @Valid 가 있어야 한다 — 마이그레이션 태스크가 생기면
    그 안에서 추가한다          ← 이 태스크를 가리키는 문장
```

있으면 그 항목을 `codebase_analysis.target_files` 에 반영한다. 읽고도 놓치면 Phase 4 의
코드 리뷰어가 처음 발견하게 되고, 그때는 Phase 3 으로 되돌아간다.

## 5. 시안 CSS 의 맥락 의존 선언은 고정값으로 옮기지 않는다 (Step 4 — 시안을 옮기는 Frontend 태스크)

시안 CSS 의 값 가운데 일부는 **놓인 자리에 따라 달라진다.** 이것을 한 자리에서 잰 고정값으로
옮기면 그 자리에서는 같아 보이고, 다른 면 위에서 깨진다. 테스트 환경(jsdom)은 배치를 계산하지
않으므로 테스트도 통과한다 — 브라우저에서야 드러난다 (→ TASK-017 Phase 4 1회차 FAIL —
배지가 「예…」로 잘리고 회색 배지가 회색 면에 묻혔다).

| 맥락 의존 선언 | 예 | 고정값으로 옮기면 |
|---|---|---|
| `var(--…)` 로 받는 값 (면이 정의) | `background: var(--c-fill)` | 다른 면 위에서 배경과 같은 색이 된다 |
| `pointer-events` | 토스트의 `none` | 아래 요소 클릭을 막는다 |
| flex 축 규칙 | `flex-shrink: 0`·`min-width: 0` | 옆 글자가 길면 줄어 말줄임된다 |
| 칸 최소 폭 | `minmax(48px, auto)` | 칸이 고정돼 내용이 넘친다 |

**PLAN 에서** 시안 CSS 를 읽어 이 선언을 따로 뽑아 `design.prop_schema` 에 적는다 — 부품마다
「어떤 면·어떤 이웃 옆에서 무엇이 달라지는가」. **시나리오 규약 표에는** 이 값을 숫자·색이 아니라
변수·규칙 그대로 적는다(`var(--c-fill)`, `flex-shrink: 0`). Phase 4 는 이 목록의 부품을 서로
다른 면 위에 놓고 브라우저에서 확인한다.

## 6. 시안 모양 값은 표로 전수 옮긴다 (Step 4 — 시안이 있는 Frontend 태스크)

§5 가 「어떻게 옮기나」라면 이 절은 「무엇을 옮기나」다. 시안의 값을 눈으로 골라 옮기면 빠진 값이
Phase 4 의 시안 대조에서 처음 나온다 (→ TASK-018 Phase 4 1회차 RC-3 — 차이 7건, 롤백 2회).

PLAN `design` 에 **「시안 모양 값」 표**를 둔다 — 행마다 화면 · 상태 · 요소 · 값 · 출처(파일:줄).

- 화면 HTML 의 `<style>` 과 `components.css` 의 **맥락 규칙**(`.plain .appbar` 처럼 부모에 따라 달라지는
  선택자)을 **전수로** 옮긴다. 이 태스크의 화면에 걸리는 선택자를 Grep 으로 열거한다
- 2a 는 이 표의 행마다 시나리오(계산된 스타일 단언 — DESIGN-002 의 토큰 탐침 대조)를 둔다
- 맥락 의존 값은 §5 대로 변수·규칙 그대로 적는다

## 7. 페이지로 나눠 받는 목록의 건수 문구는 서버 총수부터 본다 (Step 2 — 목록 화면)

페이지 응답(`page`·`size`)을 받는 목록에서 「N건」 같은 **건수 문구**를 쓰려면, 서버 응답에 **총수
필드**(`totalElements` 등)가 있는지 먼저 확인한다. 없는데 불러온 행으로 세면 「더 보기」를 누를 때마다
숫자가 바뀌어 총수처럼 읽히지 않는다 (→ TASK-025 VERIFY RC-1 — 예외 승인).

- 확인 결과를 `unresolved` 에 적는다
- 총수가 없으면 **건수 없는 문구를 기본안**으로 제시하고, 건수가 필요하면 선행 백엔드 태스크를 묻는다

## 8. 라이브러리가 읽는 설정은 키·값을 대조한다 (Step 2·4 — 외부 라이브러리 설정을 받는 태스크)

SMTP·HTTP 클라이언트·드라이버처럼 **라이브러리가 직접 읽는 설정**을 받으면, 앱이 그 값을 해석하지
않더라도 입력이다. 「앱은 넘기기만 한다(n/a)」로 닫으면 같은 뿌리의 변종이 리뷰 라운드마다 하나씩
나온다 (→ TASK-027 RC-2 — 뒤늦게 나온 변종 7, Phase 4 FAIL, 시나리오 롤백 3회).

`input_fields` 에 `external_config` 종류를 고르고, 아래를 **라이브러리 소스·문서로 확인해** PLAN 에 적는다.

| 확인 | 예 (TASK-027) |
|---|---|
| 라이브러리가 **실제로 읽는 키** — 프로토콜·모드별 접두사 | JavaMail 은 `mail.smtps.timeout` 만 읽고 `mail.smtp.*` 는 무시한다 |
| **검증한 값 == 쓰는 값** — 정리(trim)한 값을 실제로 넘기는가 | Boot 가 넣은 호스트 원문(앞뒤 공백)이 그대로 쓰였다 |
| **0·미설정의 라이브러리 기본 의미** | 타임아웃 0·미설정 = 무한 대기 |
| **다른 표기** — 설정 파일 대괄호 키·환경변수 완화 바인딩 | `spring.mail.properties[mail.smtp.timeout]` 은 `getProperty` 로 안 보인다 |

이 칸은 `n/a` 로 닫을 수 없다(`coverage_matrix.py` 가 거부한다). 해당하지 않으면 시나리오로 그 사실을 보인다.
