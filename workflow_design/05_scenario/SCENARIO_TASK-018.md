# TASK-018 시나리오

대상: `pages/LoginPage.tsx`·`SignUpPage.tsx`·`OAuthRedirectPage.tsx`·`RoleSelectionPage.tsx`(재작성), `pages/JoinedPage.tsx`(신규), `auth/messages.ts`, `auth/socialProvider.ts`(신규), `api/auth.ts`, `App.tsx`, `components/SocialLoginButtons.tsx`, `components/ui/Field.tsx`, `components/ui/{Segmented,Hero,Info}.tsx`(신규).
테스트는 서버를 두지 않는다 — "서버가 ~로 응답한다"는 `fetch` 응답(상태·본문)으로 만든다. 화면은 `App` + `MemoryRouter` + `AuthProvider` 로 실제 라우트를 지나고, 이동은 라우터의 현재 경로로 확인한다(jsdom 은 페이지를 옮기지 않는다).
토큰은 `localStorage` 의 `accessToken` (ADR-0015). 콜백 토큰은 지금처럼 query 로 온다(ADR-0021 fragment 전환은 이 태스크 밖 — PLAN #12).
요청 본문을 단언할 때는 보낸 `fetch` 의 `body` 를 `JSON.parse` 해 비교한다.

## 제가 정한 값 (시안·AC·feature 에 없는 것)

1. 오류는 제출을 한 번 시도한 뒤부터 보이고, 그 뒤엔 입력할 때마다 다시 계산한다(기존 동작). 칸 오류가 하나라도 있으면 요청을 보내지 않는다
2. 로그인 칸 검증은 비었는지만 본다 — 이메일은 공백을 뺀 값, 비밀번호는 그대로(`""` 만 빈 값). 길이·형식은 서버가 판정한다(PLAN constraints)
3. 가입 길이는 UTF-16 코드 유닛 수(`string.length`)로 세고 입력을 변환하지 않는다(서버 `@Size` 와 같게, ADR-0019). 이메일만 앞뒤 공백을 걷어 보내고, 이메일 길이도 걷은 값으로 센다. 응답의 `accessToken`·`handle` 은 걷지 않고 받은 그대로 저장·표시·복사한다
4. 화면을 떠난 뒤(언마운트) 도착한 응답은 로그인·이동·오류 표시 어디에도 쓰지 않는다 (ADR-0018)
5. 성공 응답은 응답 시점의 세션을 덮어쓴다 — 요청 사이에 다른 계정으로 로그인·로그아웃됐어도 응답의 계정으로 로그인한다(TASK-013 결정 7 과 같다)
6. 로그인·가입 완료 응답은 `accessToken`(공백만이 아닌 문자열)과 `user`(`name` 공백만이 아닌 문자열·`email` 문자열·`role` `AUDIENCE`/`ORGANIZER`·`handle` 공백만이 아닌 문자열)가 있어야 성공이다. 상태가 200 이어도 아니면 실패다. `/api/auth/me` 복원도 같은 `user` 규칙이다 (SC-35)
7. 역할 선택은 `POST /api/auth/social/pending` 응답의 `provider`(4종 대문자)·`email`·`name`(공백만이 아닌 문자열)·`expiresAt`(시각으로 읽히는 문자열)이 모두 맞을 때만 역할 행을 보인다. 아니면 「대기 정보 실패」
8. 만료는 `expiresAt` 이 가리키는 순간 **이후가 아니라 그 순간부터**(`now >= expiresAt`)다. 이미 지난 값이 오면 바로 만료 상태
9. `계속하기` 요청이 가는 중에 `expiresAt` 이 지나도 화면은 응답을 기다린다 — 판정은 서버다. 200 이면 가입 완료, 401 `PENDING_SIGNUP_EXPIRED` 면 만료 상태
10. 가입 완료 화면의 경로는 이동할 때 넘긴 라우트 state(`via`)에서 온다 — 이메일 가입은 `email`, 소셜은 대기 정보의 `provider`(PLAN #6). state 가 없거나 모르는 값이면 윗줄에 역할만 보인다(`관객`)
11. 가입 완료 화면은 로그인한 사용자만 — 복원 중이면 기다리고, 비로그인이면 `/login` 으로 바꿔 이동한다
12. 인증 화면(`/login` `/signup` `/oauth2/redirect` `/oauth2/role` `/joined`)에서는 전역 헤더(로그인·가입·로그아웃)를 그리지 않는다 (사용자 결정 2026-11-06)
13. 가입 화면에서 소셜 버튼을 뺀다 — 시안 signup 에 없다. 로그인 화면에만 있다
14. 가입 뒤 안내(`가입은 끝났어요…`)와 소셜 실패 안내는 로그인을 다시 제출하면 사라진다

**단위 테스트로 지킬 수 없는 것 → Phase 4 증거**: 375px 에서 시안과 나란히 비교한 캡처(SC-34), 서체·가로 넘침은 jsdom 이 계산하지 않는다(PLAN #13).

**이 태스크가 바꾸는 기존 테스트**: `AuthScreens.test.tsx`(TASK-010)·`SocialLoginScreens.test.tsx`(TASK-013)의 옛 문구(합니다체)·가입 뒤 `/login` 이동·`거의 다 됐어요`·토큰 디코드 안내·완료 뒤 `/` 이동·`로그인 화면으로` 버튼·가입 화면 소셜 버튼·user 픽스처의 `handle` 부재(PLAN #1·#2). 2b 에서 새 기대값으로 바꾸고 통합 승인 때 함께 보인다. 단언 수는 줄이지 않는다.

## SC-01 (happy) 로그인 화면은 시안의 요소를 보인다

- **Given** 로그인하지 않았다
- **When** `/login` 을 연다
- **Then** 제목 `쓰던 계정으로 바로 들어와요` 와 보조 문구가 보인다
- **And** `이메일` `비밀번호` 칸과 `로그인하기` 버튼이 있다
- **And** `소셜 로그인` 묶음 안에 `카카오` `네이버` `구글` `애플` 링크가 이 순서로 있다
- **And** `계정이 없나요?` 줄의 `이메일로 가입` 링크를 누르면 경로가 `/signup` 이 된다
- **And** 전역 헤더의 `로그인`·`가입` 버튼이 없다

covers: 로그인 401 이면 두 칸이 함께 오류 표시되고 "이메일 또는 비밀번호가 올바르지 않아요" 가 나온다
flow: F1

## SC-02 (error) 로그인 401 INVALID_CREDENTIALS 면 두 칸이 함께 오류가 된다

- **Given** 서버가 `/api/auth/login` 에 401 `{"code":"INVALID_CREDENTIALS"}` 로 응답한다
- **When** 이메일 `a@b.com`, 비밀번호 `wrongpass1` 로 `로그인하기` 를 누른다
- **Then** 이메일 칸과 비밀번호 칸이 모두 `aria-invalid="true"` 다
- **And** 비밀번호 칸 아래 `이메일 또는 비밀번호가 올바르지 않아요` 가 한 번만 보인다
- **And** 경로는 `/login` 그대로이고 `localStorage.accessToken` 이 없다

covers: 로그인 401 이면 두 칸이 함께 오류 표시되고 "이메일 또는 비밀번호가 올바르지 않아요" 가 나온다
flow: F1

## SC-03 (error) 로그인 응답이 판정 코드가 아니면 일반 실패 문구를 보인다

- **Given** 서버가 `/api/auth/login` 에 표의 응답을 준다
- **When** 이메일 `a@b.com`, 비밀번호 `password1` 로 `로그인하기` 를 누른다
- **Then** 표의 문구가 맨 위에 보이고 두 칸은 `aria-invalid` 가 아니다
- **And** 경로는 `/login` 그대로이고 `localStorage.accessToken` 이 없다

| 응답 | 문구 |
|---|---|
| 401 `{"code":"WRITE_KEY_INVALID"}` | `쓰기 권한 확인에 실패했습니다. 관리자에게 문의해 주세요` |
| 401 `{"code":"UNAUTHORIZED"}` (다른 code) | `로그인하지 못했어요. 잠시 후 다시 시도해 주세요` |
| 401 빈 본문 | `로그인하지 못했어요. 잠시 후 다시 시도해 주세요` |
| 500 본문 `<html>oops</html>` (비 JSON) | `로그인하지 못했어요. 잠시 후 다시 시도해 주세요` |
| 네트워크 오류(`fetch` 거부) | `로그인하지 못했어요. 잠시 후 다시 시도해 주세요` |
| 200 인데 `user.handle` 없음 | `로그인하지 못했어요. 잠시 후 다시 시도해 주세요` |
| 200 인데 `user.handle` 이 `""` · `"  "` · 숫자 `7302` · `null` (행마다) | `로그인하지 못했어요. 잠시 후 다시 시도해 주세요` |
| 200 빈 본문 | `로그인하지 못했어요. 잠시 후 다시 시도해 주세요` |

covers: 로그인 401 이면 두 칸이 함께 오류 표시되고 "이메일 또는 비밀번호가 올바르지 않아요" 가 나온다

## SC-04 (happy) 로그인에 성공하면 원래 가려던 화면으로 돌아간다

- **Given** 서버가 `/api/auth/login` 에 200 `{accessToken:"tok-1", user:{id:1,email:"a@b.com",name:"김하린",role:"AUDIENCE",handle:"wave7302"}}` 로 응답한다
- **And** `/login` 으로 올 때 라우트 state 의 `from` 이 표의 값이다
- **When** 이메일·비밀번호를 넣고 `로그인하기` 를 누른다
- **Then** `localStorage.accessToken` 이 `tok-1` 이다
- **And** 경로가 표의 이동 위치가 된다

| `from` | 이동 위치 |
|---|---|
| 없음(state 없음) | `/` |
| `null` | `/` |
| `42` (숫자) · `{pathname:"/x"}` (객체) (행마다) | `/` |
| `/performances/7?tab=seat#top` | `/performances/7?tab=seat#top` |
| `//evil.example` | `/` |
| `https://evil.example/x` | `/` |
| `/\evil.example` | `/` |
| ` /performances/7` (앞 공백) | `/` |
| `/performances/7\n` (끝 LF) | `/performances/7\n` 그대로 — 앱 안 경로 |
| `/login?x=1` | `/` |
| `/signup` | `/` |

covers: 로그인 성공 시 원래 가려던 화면으로 돌아간다 (기존 동작 유지)
flow: F1

## SC-05 (error) 로그인 칸이 비면 요청하지 않고, 값은 바꾸지 않고 보낸다

- **Given** 로그인 화면이다
- **When** 표의 이메일·비밀번호로 `로그인하기` 를 누른다
- **Then** 표의 결과가 된다

| 이메일 | 비밀번호 | 결과 |
|---|---|---|
| `""` | `password1` | 이메일 칸 아래 `이메일을 입력해 주세요`, 요청 없음 |
