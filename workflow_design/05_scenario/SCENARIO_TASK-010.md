# TASK-010 시나리오

대상: `frontend/src/api/auth.ts`, `auth/AuthContext.tsx`, `pages/SignUpPage.tsx`, `pages/LoginPage.tsx`, `components/AppHeader.tsx`, `App.tsx`(라우트 `/signup`·`/login`).
테스트는 서버를 두지 않는다 — 시나리오의 "서버가 ~로 응답한다"는 `fetch` 응답(상태·본문)으로 만든다.

## 화면 문구 (정본)

시나리오가 이 문구를 그대로 단언한다. 바꾸려면 여기부터 고친다.

| 위치 | 문구 |
|---|---|
| 가입 필드 라벨 | `이메일` `비밀번호` `비밀번호 확인` `이름` / 역할 라디오 `관객` `주최자` / 버튼 `가입하기` |
| 로그인 필드 라벨 | `이메일` `비밀번호` / 버튼 `로그인` |
| 비밀번호 불일치 | `비밀번호가 일치하지 않습니다` |
| 필수 입력 | `이메일을 입력해 주세요` · `비밀번호를 입력해 주세요` · `비밀번호를 한 번 더 입력해 주세요` · `이름을 입력해 주세요` · `역할을 선택해 주세요` |
| 길이 | `비밀번호는 8자 이상이어야 합니다` · `비밀번호는 72자 이하여야 합니다` · `이름은 100자 이하여야 합니다` · `이메일은 255자 이하여야 합니다` |
| 이메일 중복 | `이미 가입된 이메일입니다. 로그인해 주세요` + 링크 `로그인`(→ `/login`) |
| 로그인 실패 | `이메일 또는 비밀번호가 올바르지 않습니다` |
| 가입 일반 실패 | `가입하지 못했습니다. 잠시 후 다시 시도해 주세요` |
| 로그인 일반 실패 | `로그인하지 못했습니다. 잠시 후 다시 시도해 주세요` |
| 쓰기 거부 | `WRITE_REJECTED_MESSAGE` (`쓰기 권한 확인에 실패했습니다. 관리자에게 문의해 주세요`) |
| 헤더 | 비로그인 `로그인` `가입` 링크 / 로그인 `<이름>` 텍스트 + `로그아웃` 버튼 |

토큰은 `localStorage` 의 키 `accessToken` 에 저장한다 (ADR-0015).

## SC-01 (happy) 가입 화면의 기본 상태

- **Given** 로그인하지 않았고 `localStorage` 에 토큰이 없다
- **When** `/signup` 을 연다
- **Then** `이메일` `비밀번호` `비밀번호 확인` `이름` 입력란과 역할 라디오 `관객` `주최자`, 버튼 `가입하기` 가 있다
- **And** 역할 라디오는 둘 다 선택되어 있지 않고, 오류 문구는 하나도 보이지 않는다
- **And** `이메일` 입력란에 포커스가 있다

covers: 회원가입 성공 시 로그인 화면으로 이동한다
flow: F2

## SC-02 (happy) 로그인 화면의 기본 상태

- **Given** 로그인하지 않았고 `localStorage` 에 토큰이 없다
- **When** `/login` 을 연다
- **Then** `이메일` `비밀번호` 입력란과 버튼 `로그인` 이 있고 오류 문구는 보이지 않는다
- **And** `이메일` 입력란에 포커스가 있다

covers: 로그인 성공 시 토큰을 저장하고 이전 화면(또는 홈)으로 이동한다
flow: F4

## SC-03 (happy) 가입에 성공하면 역할 포함해 요청하고 로그인 화면으로 이동한다

- **Given** `/signup` 에서 이메일 `hong@example.com`, 비밀번호 `password1!`, 비밀번호 확인 `password1!`, 이름 `홍길동`, 역할 `주최자` 를 입력했다
- **And** 서버가 `POST /api/auth/signup` 에 201 과 사용자 정보로 응답한다
- **When** `가입하기` 를 누른다
- **Then** 요청 본문이 `{"email":"hong@example.com","password":"password1!","passwordConfirm":"password1!","name":"홍길동","role":"ORGANIZER"}` 이다 (`관객` 이면 `AUDIENCE`)
- **And** 화면이 `/login` 으로 이동해 로그인 화면(`로그인` 버튼)이 보인다
- **And** `localStorage` 에 `accessToken` 이 저장되지 않는다 (가입은 로그인이 아니다)

covers: 회원가입 성공 시 로그인 화면으로 이동한다
flow: F2

## SC-04 (error) 비밀번호 확인이 다르면 제출 전에 인라인 오류를 보인다

- **Given** `/signup` 에서 비밀번호 `password1!`, 비밀번호 확인 `password2!` 를 입력하고 나머지 필드는 올바르게 채웠다
- **When** `가입하기` 를 누른다
- **Then** `비밀번호 확인` 입력란 아래에 `비밀번호가 일치하지 않습니다` 가 보이고 그 입력란이 `aria-invalid="true"` 이다
- **And** 서버로 어떤 요청도 가지 않는다
- **And** `/signup` 화면에 머문다

covers: 회원가입 폼에서 비밀번호와 비밀번호 확인이 다르면 제출 전 인라인 오류를 표시한다
flow: F1

## SC-07 (error) 필수 입력과 길이 위반은 서버로 보내지 않고 필드 아래에 알린다

- **Given** 아래 표의 위반 하나만 있고 나머지 필드는 올바르게 채워진 폼이다
- **When** 제출 버튼(`가입하기` / `로그인`)을 누른다
- **Then** 해당 입력란 아래에 표의 문구가 보이고 그 입력란이 `aria-invalid="true"` 이다
- **And** 서버로 어떤 요청도 가지 않는다

| 화면 | 위반 | 문구 |
|---|---|---|
| 가입 | 이메일 빈 값 | `이메일을 입력해 주세요` |
| 가입 | 이메일 공백만 (`   `) | `이메일을 입력해 주세요` |
| 가입 | 비밀번호 빈 값 | `비밀번호를 입력해 주세요` |
| 가입 | 비밀번호 공백만 8자 (`        `) | `비밀번호를 입력해 주세요` |
| 가입 | 비밀번호 7자 (`abcdefg`) | `비밀번호는 8자 이상이어야 합니다` |
| 가입 | 비밀번호 73자 | `비밀번호는 72자 이하여야 합니다` |
| 가입 | 비밀번호 확인 빈 값 (`""`) | `비밀번호를 한 번 더 입력해 주세요` |
| 가입 | 비밀번호 확인 공백만 (비밀번호는 `password1!`) — 값이 있으므로 필수가 아니라 불일치로 본다 | `비밀번호가 일치하지 않습니다` |
| 가입 | 이름 빈 값 / 공백만 | `이름을 입력해 주세요` |
| 가입 | 이름 101자 | `이름은 100자 이하여야 합니다` |
| 가입 | 이메일 256자 | `이메일은 255자 이하여야 합니다` |
| 가입 | 역할 미선택 | `역할을 선택해 주세요` |
| 로그인 | 이메일 빈 값 / 공백만 | `이메일을 입력해 주세요` |
| 로그인 | 비밀번호 빈 값 | `비밀번호를 입력해 주세요` |

경계: 비밀번호 8자(`abcdefgh`)·72자, 이름 100자, 이메일 255자는 통과해 서버로 요청이 간다. 길이는 서버 `@Size` 와 같게 UTF-16 코드 유닛 수(JS `string.length`)로 센다.
경계: **로그인** 입력은 길이 상한을 클라이언트가 검증하지 않는다 (SC-32). 로그인 비밀번호가 공백만(`        `)이어도 클라이언트는 막지 않고 요청이 간다 (가입의 공백만 비밀번호 거부와 의도적으로 다르다 — 로그인 판정은 서버가 한다).
경계: 비밀번호가 문자 수 72자 이하여도 UTF-8 로 72바이트를 넘는 경우(한글 25자)는 클라이언트가 막지 않고 요청이 간다 — 서버 판단은 SC-11·SC-16.

covers: 회원가입 폼에서 비밀번호와 비밀번호 확인이 다르면 제출 전 인라인 오류를 표시한다; 로그인 실패(401) 시 "이메일 또는 비밀번호가 올바르지 않습니다"를 표시한다
flow: F1, F4

## SC-08 (boundary) 가입 입력은 이메일 앞뒤 공백만 제거하고 나머지는 변환 없이 보낸다

- **Given** 가입 폼의 나머지 필드는 올바르게 채웠고, 아래 표의 필드 하나에 표의 값을 입력했다 (비밀번호는 확인란에도 같은 값)
- **When** `가입하기` 를 누른다
- **Then** 요청 본문의 해당 필드가 "전송 값" 과 정확히 같다 (프론트는 거부·변환하지 않는다 — 판단은 서버가 한다)
- **And** 다른 필드는 올바른 값 그대로다

| 필드 | 입력 | 전송 값 |
|---|---|---|
| email | `  hong@example.com  ` | `hong@example.com` (앞뒤 공백만 제거) |
| email | `a\u0000b@example.com` (NUL) | 그대로 |
| email | `a\ud800b@example.com` (짝 없는 서로게이트) | 그대로 |
| password (+ 확인) | ` pass word1 ` (앞뒤·중간 공백) | 그대로 |
| password (+ 확인) | `pass\u0000word1` (NUL) | 그대로 |
| password (+ 확인) | `pass\ud800word1` (짝 없는 서로게이트) | 그대로 |
| name | `홍\u0000길동😀` (NUL + 이모지) | 그대로 |
| name | `홍\ud800길동` (짝 없는 서로게이트) | 그대로 |

covers: 회원가입 성공 시 로그인 화면으로 이동한다
flow: F2

## SC-09 (boundary) 로그인 입력도 이메일 앞뒤 공백만 제거하고 나머지는 변환 없이 보낸다

- **Given** 로그인 폼의 나머지 필드는 올바르게 채웠고, 아래 표의 필드 하나에 표의 값을 입력했다
- **When** `로그인` 을 누른다
- **Then** 요청 본문의 해당 필드가 "전송 값" 과 정확히 같다
- **And** 요청 본문 전체의 키는 `email`, `password` 둘뿐이다

| 필드 | 입력 | 전송 값 |
|---|---|---|
| email | `  hong@example.com  ` | `hong@example.com` |
| email | `a\u0000b@example.com` (NUL) | 그대로 |
| email | `a\ud800b@example.com` (짝 없는 서로게이트) | 그대로 |
| password | ` pass word1 ` | 그대로 |
| password | `pass\u0000word1` (NUL) | 그대로 |
| password | `pass\ud800word1` (짝 없는 서로게이트) | 그대로 |

covers: 로그인 성공 시 토큰을 저장하고 이전 화면(또는 홈)으로 이동한다

## SC-10 (error) 이메일이 중복이면 전용 메시지와 로그인 링크를 보인다

- **Given** 올바르게 채운 가입 폼이다
- **And** 서버가 409 와 `{"code":"EMAIL_ALREADY_EXISTS","message":"..."}` 로 응답한다
- **When** `가입하기` 를 누른다
- **Then** `이미 가입된 이메일입니다. 로그인해 주세요` 가 보이고, 그 안에 `/login` 으로 가는 링크 `로그인` 이 있다
- **And** 이메일·이름·역할과 두 비밀번호 입력란의 값이 그대로 남아 있다
- **And** 화면은 `/signup` 에 머물고 `가입하지 못했습니다...` 일반 문구는 보이지 않는다

covers: 이메일 중복(409) 응답 시 전용 오류 메시지와 로그인 링크를 표시한다
flow: F3

## SC-11 (error) 중복이 아닌 가입 실패는 일반 문구로 보이고 중복 문구가 새지 않는다

- **Given** 올바르게 채운 가입 폼이다
- **And** 서버가 `POST /api/auth/signup` 에 아래 표의 응답을 준다
- **When** `가입하기` 를 누른다
- **Then** 표의 문구가 보인다
- **And** 어느 경우에도 `/signup` 에 머물고 `localStorage` 에 토큰이 저장되지 않는다
- **And** 이메일·이름·역할과 두 비밀번호 입력란의 값이 그대로 남고 `가입하기` 버튼은 다시 눌러진다

| 응답 | 문구 |
|---|---|
| 409 + `{"code":"SOMETHING_ELSE"}` (code 다름) | `가입하지 못했습니다. 잠시 후 다시 시도해 주세요` |
| 409 + 빈 바디 | 같음 |
| 400 + `{"code":"INVALID_REQUEST","message":"password: UTF-8 기준 72바이트를 넘을 수 없습니다"}` — 한글 25자(75바이트) 비밀번호 | 같음 |
| 400 + `{"code":"INVALID_REQUEST","message":"name: ..."}` — NUL·짝 없는 서로게이트가 든 이름 | 같음 |
| 400 + `{"code":"INVALID_REQUEST","message":"email: ..."}` — 형식이 틀린 이메일(`abc`)·NUL·짝 없는 서로게이트가 든 이메일 | 같음 |
| 500 + 비 JSON 텍스트 | 같음 |
| 임의 JSON(`{"foo":1}`) + 201 이 아닌 상태 | 같음 |
| `fetch` 가 네트워크 오류로 reject | 같음 |
| 401 + `{"code":"WRITE_KEY_INVALID"}` (쓰기 가드) | `쓰기 권한 확인에 실패했습니다. 관리자에게 문의해 주세요` |

covers: 이메일 중복(409) 응답 시 전용 오류 메시지와 로그인 링크를 표시한다
flow: F3

## SC-12 (boundary) 제출 중에는 버튼이 비활성이고 중복 요청이 가지 않는다

- **Given** 올바르게 채운 폼(가입 `가입하기` / 로그인 `로그인`)이고, 서버 응답이 아직 오지 않는다
- **When** 제출 버튼을 두 번 연속 누른다
- **Then** 서버로 가는 요청은 한 번뿐이다
- **And** 응답이 오기 전까지 버튼은 `disabled` 이다
- **And** 오류 응답(500)이 오면 버튼이 다시 활성화된다

covers: 회원가입 성공 시 로그인 화면으로 이동한다; 로그인 성공 시 토큰을 저장하고 이전 화면(또는 홈)으로 이동한다
flow: F2, F4

## SC-13 (happy) 헤더 링크로 온 로그인에 성공하면 토큰을 저장하고 이전 화면으로 이동한다

- **Given** 헤더의 `로그인` 링크로 `/performances/3` 에서 `/login` 에 왔다 (이전 화면 = `/performances/3`)
- **And** 서버가 `POST /api/auth/login` 에 200 과 `{"accessToken":"tok-1","tokenType":"Bearer","expiresInSeconds":86400,"user":{"id":1,"email":"hong@example.com","name":"홍길동","role":"AUDIENCE"}}` 로 응답한다
- **And** 로그인 폼에 이메일 `hong@example.com`, 비밀번호 `password1!` 를 입력해 두었다
- **When** `로그인` 을 누른다
- **Then** 요청 본문이 `{"email":"hong@example.com","password":"password1!"}` 이다
- **And** `localStorage` 의 `accessToken` 이 `tok-1` 이다
- **And** 화면이 `/performances/3` 으로 이동한다

covers: 로그인 성공 시 토큰을 저장하고 이전 화면(또는 홈)으로 이동한다
flow: F4

## SC-15 (boundary) 이전 화면은 앱 안의 경로만 믿는다

- **Given** `/login` 에 들어올 때 이전 화면 정보(`location.state.from`)가 아래 값이다
- **And** 서버가 로그인에 200 으로 응답하고 올바른 이메일·비밀번호가 입력돼 있다
- **When** `로그인` 을 누른다
- **Then** 표의 이동 결과가 된다

| `from` | 이동 |
|---|---|
| 이전 화면 정보 없음 (`/login` 으로 직접 옴) | `/` |
| `/performances/3?tab=a#x` | 그대로 `/performances/3?tab=a#x` |
| `https://evil.example/` | `/` |
| `//evil.example/` | `/` |
| `javascript:alert(1)` | `/` |
| `/login` 또는 `/signup` | `/` (로그인 화면으로 되돌아가는 순환 방지) |
| 빈 문자열 · 숫자 · 객체 | `/` |
