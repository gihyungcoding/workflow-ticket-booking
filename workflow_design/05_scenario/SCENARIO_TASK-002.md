# TASK-002 시나리오

총 6건 — happy 2 / error 2 / boundary 2. `regression` 은 생략한다: 이 태스크는 이 프로젝트의
첫 프론트엔드 화면이라 되돌릴 기존 동작이 없다.

## SC-01 (happy) 목록에 공연이 카드와 상태 배지로 표시된다

- **Given** `GET /api/performances` 가 공연 2건을 담은 200 응답을 반환한다 — 제목
  "재즈의 밤"인 공연은 `status: "OPEN"`, 제목 "클래식 갈라"인 공연은
  `status: "SOLD_OUT"`이다
- **When** 관객이 공연 목록 화면에 진입한다
- **Then** 카드가 2개 렌더된다
- **And** 각 카드에 제목·장소·공연 일시가 보인다
- **And** 제목이 "재즈의 밤"인 카드에는 "예매가능" 배지가 보인다
- **And** 제목이 "클래식 갈라"인 카드에는 "매진" 배지가 보인다

covers: 목록 화면 진입 시 API 응답의 공연이 카드로 표시되고 각 카드에 상태 배지가 보인다
flow: F1

## SC-02 (happy) 상세 화면에 공연 정보 전체가 표시된다

- **Given** `GET /api/performances/{id}` 가 공연 1건(title, venue, startAt, openAt,
  closeAt, availableSeats, `status: "OPEN"`)을 담은 200 응답을 반환한다
- **When** 관객이 해당 id의 공연 상세 화면에 진입한다
- **Then** 화면에 공연명·장소·공연 일시·오픈 시각·마감 시각·잔여 좌석 수가 보인다
- **And** "예매가능" 상태 배지가 보인다

covers: 상세 화면에서 공연명·장소·일시·오픈/마감 시각·잔여 좌석·상태 배지가 표시된다
flow: F5

## SC-03 (error) 목록 API 호출 실패 시 오류 메시지와 다시 시도 버튼이 표시된다

- **Given** `GET /api/performances` 가 500 응답을 반환한다
- **When** 관객이 공연 목록 화면에 진입한다
- **Then** "목록을 불러오지 못했습니다" 오류 메시지가 보인다
- **And** [다시 시도] 버튼이 보인다

covers: 목록 API 호출이 실패하면 오류 메시지와 다시 시도 버튼이 표시된다
flow: F4

## SC-04 (error) 존재하지 않는 공연 상세는 404 안내를 보여준다

- **Given** `GET /api/performances/{id}` 가 404와 `{code: "PERFORMANCE_NOT_FOUND"}` 를
  반환한다
- **When** 관객이 해당 id의 공연 상세 화면에 진입한다
- **Then** "존재하지 않는 공연입니다" 안내가 보인다
- **And** [목록으로] 버튼이 보인다

covers: 존재하지 않는 공연 상세로 진입(404)하면 존재하지 않는 공연입니다 안내와 목록으로 돌아가는 버튼이 표시된다
flow: F6

## SC-05 (boundary) 로딩 중에는 스켈레톤이 표시된다

- **Given** `GET /api/performances` 요청이 아직 응답하지 않은 상태(pending)다
- **When** 관객이 공연 목록 화면에 진입한다
- **Then** 카드 자리에 스켈레톤이 3개 이상 보인다
- **And** 실제 공연 카드는 보이지 않는다

covers: 로딩 중에는 카드 자리에 스켈레톤이 표시된다
flow: F2

## SC-06 (boundary) 목록이 빈 배열이면 안내 문구가 표시된다

- **Given** `GET /api/performances` 가 `content: []` 를 담은 200 응답을 반환한다
- **When** 관객이 공연 목록 화면에 진입한다
- **Then** "예정된 공연이 없습니다" 안내가 보인다
- **And** 카드가 하나도 렌더되지 않는다

covers: 목록이 빈 배열이면 예정된 공연이 없습니다 안내가 표시된다
flow: F3

---

## 생략 이유

- `regression`: 이 태스크는 최초의 프론트엔드 화면이라 되돌릴 기존 동작이 없다
- F7(상세 로딩 스켈레톤): `PLAN_TASK-002.json` 에서 공식 `acceptance_criteria` 가 아니라고
  이미 기록됨 (`covers: []`) — 이번 태스크의 시나리오/테스트 범위에서 제외한다
- [다시 시도]/[목록으로] 버튼 클릭 후 실제 이동·재요청 동작: 공식 `acceptance_criteria`는
  "표시된다"까지만 요구한다. 클릭 후 동작은 새로운 `When`이 되어 별도 시나리오가
  필요하지만, AC 범위 밖이라 이번 태스크에서는 다루지 않는다

## 독립검증 반영 (VALIDATION_TASK-002.json V5)

- SC-01: "첫 번째/두 번째 카드" 위치 기반 단언을 제목("재즈의 밤"/"클래식 갈라") 기반으로
  바꿨다 — 응답 순서가 렌더 순서와 같다는, Plan에 없는 전제에 기대지 않기 위함
- SC-03: Given을 "500 응답 또는 네트워크 오류"에서 "500 응답"으로 좁혔다 — Red 단계에서
  재현할 대상을 하나로 확정하기 위함. 네트워크 예외(fetch reject)도 같은 오류 UI 경로를
  타야 하지만 이는 구현이 동일한 catch 경로를 쓰기만 하면 되는 문제라 별도 시나리오로
  분리하지 않는다(coverage-policy §3 — 같은 코드 경로)
