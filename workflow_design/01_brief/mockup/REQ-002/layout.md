# REQ-002 데스크톱 배치 계획 (1280)

## 1. 묶기

"사용자가 이 화면들을 오가며 같은 일을 하는가?"

- 좌석 고르기 ↔ 선점 확인 ↔ 무통장 예약: 모바일은 `seats` → `hold` 두 장이지만 데스크톱에서는 **좌석도를 계속 보면서**
  오른쪽 보조 열만 「선택 요약 → 선점 중 예약」으로 바뀐다. 상태마다 한 파일(`d-seats`, `d-hold`, 오류 3종).
- 내 예매 목록 ↔ 예매 상세: 관객이 여러 예매를 오가며 상태를 확인한다 → **목록·상세 나란히** 한 화면(`d-bookings`).
  확정·취소된 예매는 같은 화면에서 선택 행만 바뀐 상태 파일.
- 예약 결과(`reserved`)는 한 번 보고 은행 앱으로 넘어가는 결과 화면 — 따로 둔다.

## 2. 도메인에서 끌어낸 구조

- 대상은 **상태를 따라** 쌓인다(선점 → 입금 대기 → 예매 확정 / 자동 취소). 하지만 관객 한 명의 예매는 몇 건뿐이라
  상태 보드·표 + 필터는 과하다(30건 미만) → 목록·상세 나란히.
- 좌석은 **위치(열·번호)** 를 따라 놓인다 — 좌석도가 가장 큰 면적. 이 앱의 사실: 한 번에 최대 4석, 7분 제한이라
  고른 좌석·남은 시간·금액이 좌석도 옆에 **늘 보여야** 한다 → 보조 열(sticky).
- 앱 안 목적지가 2곳(공연·내 예매)이라 사이드 내비를 두지 않는다(desktop.md §2 — 3곳 이상일 때만).
- 무통장 결과의 주인공은 계좌·금액·기한 세 숫자 — 넓은 화면에서는 세 값을 한 줄 숫자 요약(`stats`)으로 나란히.

## 3. 데스크톱 화면

| id | 묶는 모바일 화면 | 패턴 | 주인공 | 이 앱의 사실 |
|---|---|---|---|---|
| d-seats | seats | 보조 열 (좌석도 + 선택 요약) | 좌석도 | 최대 4석 — 선택 수가 늘 보인다 |
| d-seats--taken | seats--taken | 보조 열 | 좌석도 + 빠진 좌석 안내 | 오픈 순간 동시 선점(AC-2·7) |
| d-seats--limit | seats--limit | 보조 열 | 좌석도 + 4석 한도 안내 | 1인 최대 4장 |
| d-seats--expired | seats--expired | 보조 열 | 좌석도 + 만료 안내 | 선점 7분 |
| d-hold | hold | 보조 열 (좌석도 + 예약 패널) | 남은 시간 + 예약 패널 | 7분 안에 예약 |
| d-reserved | reserved | 숫자 요약 + 보조 열 | 계좌·금액·기한 3칸 | 기한은 예약 당일 오후 11:59 |
| d-bookings | bookings, booking | 목록·상세 나란히 | 선택한 예매의 입금 정보·진행 | 관객 한 명의 예매는 몇 건 |
| d-bookings--empty | bookings--empty | 목록·상세 나란히(빈 상태) | 빈 안내 | 첫 사용 |
| d-bookings--confirmed | bookings--confirmed, booking--confirmed | 목록·상세 나란히 | 예매 확정 상세 | 입금 확인 시각 |
| d-bookings--cancelled | booking--cancelled | 목록·상세 나란히 | 자동 취소 상세 | 입금 기한 경과 |

### d-seats (상태 파일 d-seats--taken · --limit · --expired 도 같은 틀)
```
┌───────────────────────────────────────────────┬──────────────────────┐
│ 머리: 공연명 · 일시 · 장소        [등급 R석|S석] │ 보조 열 (sticky)      │
├───────────────────────────────────────────────┤  고른 좌석 3 / 4      │
│ (상태 파일: 오류·만료 안내 한 줄)                │  R-B4 · R-B5 · R-B6   │
│                 무대                           │  금액 297,000원       │
│   A  □ □ ■ ■ □ ■ ■                             │  [좌석 선점하기]       │
│   B  ■ □ ▣ ▣ ▣ □ ■     좌석도 (가장 큰 면적)    │  선점 7분 · 무통장 안내 │
│   …                                            │                      │
│   범례: 고를 수 있음 · 고를 수 없음 · 내가 고름   │                      │
└───────────────────────────────────────────────┴──────────────────────┘
```
모바일을 늘린 것과 다른 점: 좌석도와 선택 요약이 나란히 있어 좌석을 바꾸면서 금액·선택 수를 스크롤 없이 본다.

### d-hold
```
┌───────────────────────────────────────────────┬──────────────────────┐
│ 머리: 「6:42 안에 예약하면 이 자리가 내 것」     │ 예약 패널             │
│ 좌석도 (내 선점 3석 표시, 다른 좌석 고르기 막힘)   │  남은 시간 6:42 (큰 수) │
│                                               │  좌석 3 · 297,000원   │
│                                               │  결제 무통장 입금      │
│                                               │  입금자명 = 예약자 이름 │
│                                               │  [좌석 다시 고르기]     │
│                                               │  [무통장 예약하기]      │
└───────────────────────────────────────────────┴──────────────────────┘
```
모바일을 늘린 것과 다른 점: 선점한 좌석의 위치를 좌석도에서 계속 확인하며 예약한다(모바일은 좌석 목록 글자만).

### d-reserved
```
┌───────────────────────────────────────────────┬──────────────────────┐
│ 머리: 예약했어요 — 오늘 오후 11:59까지 입금     │ 다음에 일어나는 일     │
│ ┌계좌──────────┐┌금액────────┐┌기한─────────┐  │  타임라인: 예약 →      │
│ │국민 123401…  ││297,000원   ││오늘 11:59   │  │  입금 확인 → 확정      │
│ └[계좌 복사]───┘└────────────┘└─────────────┘  │  기한 지나면 자동 취소  │
│ 예약 내용 블록: 공연 · 좌석 3 · 예매번호         │  [확인] → 내 예매       │
└───────────────────────────────────────────────┴──────────────────────┘
```
모바일을 늘린 것과 다른 점: 세 값이 한 줄에 나란히 있어 은행 앱 옆에 띄워 두고 그대로 옮겨 적는다.

### d-bookings (상태 파일 --empty · --confirmed · --cancelled)
```
┌──────────────────┬────────────────────────────────────────────┐
│ 내 예매 목록       │ 상세: 상태 배지 · 공연 · 좌석               │
│ ▶ 밤의 정원 입금대기│ 입금 계좌 · 금액 · 기한 (입금 대기일 때)      │
│   밤의 정원 취소됨  │ 진행 타임라인(선점 → 예약 → 입금 확인 → 확정) │
└──────────────────┴────────────────────────────────────────────┘
```
모바일을 늘린 것과 다른 점: 다른 예매로 넘어가도 목록이 그대로 보이고, 상태가 바뀐 예매를 목록 배지와 상세에서 동시에 본다.
